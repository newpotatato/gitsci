# Проверка проекта

Все проверки детерминированные, LLM для них не нужна. Твоя задача — запустить, прочитать отчёт
и исправить, не ломая смысл текста.

## 1. Запуск

```bash
gitsci all            # всё, как в CI
gitsci latex          # формат по профилю + стиль + авторы
gitsci bib            # DOI ↔ название через Crossref (кэш в .gitsci-cache/)
gitsci figures        # шрифты, дальтонизм, разрешение
gitsci plan           # порядок RU → апрув → EN, сроки
gitsci exp check      # у каждого запуска есть версия кода и результат
```

## 2. Как исправлять

| Правило | Что делать |
|---|---|
| STYLE_SEMICOLON, STYLE_*DASH | Перестроить предложение по правилам skill `lab-writing-style` |
| STYLE_CONTRAST, STYLE_WATER | Убрать оборот, сказать прямо; если без него теряется смысл — оставить и объяснить в MR |
| EQ_FRAGMENTED, EQ_BLANK_LINE | Собрать формулу в одну строку |
| BIB_DOI_TITLE_MISMATCH | DOI ведёт на другую статью. **Не подбирать DOI самому.** Взять из подсказки (название по DOI) и спросить человека, какая статья имелась в виду |
| BIB_DOI_MISSING | Если в подсказке найден DOI с совпадающим названием — добавить; иначе спросить |
| AUTH_NAME_SPELLING | Исправить на написание из реестра (в подсказке) |
| PLAN_EN_BEFORE_APPROVAL | Не переводить раньше апрува: убрать EN-текст из коммита, оставить RU |
| FIG_CVD, FIG_FONT_SMALL | Перестроить график через `gitsci.mpl.use_style()` и `gitsci.mpl.save()` |
| EXP_* | Перезапустить эксперимент через `gitsci exp run` |

## 3. Чего не делать

- Не менять `plan.yml` статусы на `approved_ru` — это делает только руководитель.
- Не выключать правила в профиле, чтобы «позеленить» CI.
- Не редактировать `experiments/runs/` вручную.
