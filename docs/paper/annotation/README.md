# Разметка для статьи: инструкция

Три файла, все открываются в Excel. Разметку делайте независимо, не заглядывая в
`requirements.md`, `bench/precision.csv` и `bench/holdout_precision.csv`: там стоит разметка
первого разметчика. Первым разметчиком была языковая модель, поэтому ваша разметка в статье
служит единственной независимой проверкой точности.

## 1. requirements_sheet.csv (46 строк, около 15 минут)

Для каждого требования журнала заполните столбец «Автоматизируемо»:

- **А** — проверку можно сделать программой без участия человека, и она всегда даёт однозначный ответ
  (например, «аннотация не длиннее 250 слов»);
- **Ч** — программа может проверить только часть требования или с помощью эвристики, остальное решает человек
  (например, «сокращения расшифрованы при первом упоминании»);
- **Н** — нужна экспертная оценка (например, «аннотация отражает цель, методы и результаты»).

Оценивается, можно ли проверить в принципе, а не умеет ли это какой-то конкретный инструмент.
Если сомневаетесь, напишите это в «Комментарии».

## 2. precision_spotcheck.csv и precision_spotcheck_holdout.csv (по 15 строк, около 15 минут на файл)

Это замечания gitsci на опубликованных статьях с arXiv: первый файл с настроечной выборки, второй с
отложенной, на ней получена главная цифра статьи. Для каждого прочитайте фрагмент исходника
и ответьте в «Верно?»: **да**, если в статье действительно нарушено требование из замечания, **нет**, если
замечание ошибочное.

Для замечания «формула пронумерована, но на неё нет ссылки» ссылкой считается и `\ref`/`\eqref`,
и номер, вписанный вручную в текст, например «из (1.2) следует». Если для ответа фрагмента мало,
полный исходник лежит в `bench/corpus/<номер arXiv>/` или `bench/corpus_holdout/<номер arXiv>/`.

## После разметки

Сохраните файлы под теми же именами, разделитель «;». Согласие разметчиков считается так:

```
python bench/agreement.py
```
